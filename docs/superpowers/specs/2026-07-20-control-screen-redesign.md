# Q60S 车辆控制屏重设计

## 目标

将当前偏原型的控制页重做为接近用户参考图的深色车辆遥控界面。保留现有 BLE 扫描、指定设备连接、锁车、开锁、尾箱、重试和日志能力，不改变协议及安全规则。

## 设计方向

采用“车辆为主角、控制器为焦点”的单屏纵向构图：顶部只承载身份、连接状态和日志入口；中部以较大的 Q60S 俯视图建立视觉重心；下部使用紧凑的红黑组合控制器，中央锁车是主操作，开锁和尾箱为左右辅助操作。

该方案比保留现有三圆按钮更接近参考图，也比增加车辆信息面板更符合当前功能规模。

## 信息层级

1. 顶栏：返回式装饰位不增加无意义入口；左侧显示 `Q60S`，右侧提供低干扰的日志图标按钮。
2. 连接信息：车辆名下方显示 `RM3` 和当前连接状态。扫描、连接、失败与就绪使用文字和小型状态点表达。
3. 车辆舞台：俯视车辆占据屏幕上半部主要面积。尾箱指令成功后切换为尾箱开启素材并显示短暂红色尾部光晕。
4. 控制器：锁车位于中心并最大；开锁和尾箱位于两侧。操作标签保持可见，不依赖用户识别图标。

## 视觉系统

- 背景：近黑色，避免纯黑带来的层次丢失。
- 表面：石墨黑和深灰，用高光、内阴影与有限边线表达实体控制器。
- 主色：性能红，只用于中央主操作、工作状态和尾箱反馈。
- 字体：系统无衬线，标题克制，连接状态使用较小字号。
- 形状：中央控制器使用纵向胶囊轮廓，辅助按钮保持圆形；避免当前过大的浅灰圆形。
- 比例：车辆明显放大，控制器整体收紧，垂直间距根据可用高度分配，避免中间和底部出现失控留白。

## 交互状态

### 未连接

控制器保留完整红黑外观，不使用整组灰色遮罩。按钮不可点击，通过降低图标与标签亮度、状态文案 `连接 RM3 后可操作` 和禁用属性共同表达不可用。

### 扫描与连接

顶部状态点进行轻微呼吸；控制区不播放装饰性动画。

### 已连接

状态点转绿，三个按钮恢复完整对比度。按下使用 150–180ms 的缩放和亮度反馈。

### 指令发送

仅当前按钮显示简短忙碌状态，防止重复触发。结果继续复用现有成功或失败提示。

### 失败

状态行提供 `重新扫描`，日志入口始终可用。错误不覆盖车辆和控制器。

## 响应式与平台约束

- 继续使用 `--status-bar-height` 和底部安全区，避免 Android 状态栏及 iOS Home Indicator 遮挡。
- Android 触控目标至少 48dp，iOS 至少 44pt。
- 矮屏优先缩小车辆舞台和纵向间距，不改变控制器的触控尺寸。
- 窄屏保持三键横向结构；不再把按钮改成纵向列表。
- 尊重系统减少动态效果设置。

## 组件边界

- `ConnectionHeader.vue`：车辆身份、连接状态、重试与日志入口。
- `VehicleHero.vue`：车辆素材、就绪与尾箱反馈。
- `VehicleControlButton.vue`：单个辅助操作按钮及交互状态。
- `control.vue`：页面构图和中央组合控制器，不触碰 BLE 服务与领域逻辑。

## 验收标准

- 真机首屏构图与参考图属于同一视觉语言：大车体、红黑中央控制器、紧凑辅助键。
- 未连接时界面仍保持红黑质感，但任何车辆指令都不能发出。
- 连接后原有三项指令、日志、重试和尾箱反馈均可用。
- Android 真机状态栏不遮挡内容，底部系统导航区不遮挡按钮。
- 现有自动化测试通过，并新增关键结构与禁用状态的界面契约测试。
